# Polyvent

PolEvent — веб-сервис внеучебных мероприятий кампуса ЯГТУ. Студенты находят события в общей афише, организаторы готовят объявления, а модераторы проверяют их перед публикацией.

Этот репозиторий содержит последовательный перенос и развитие проекта, исходная версия которого находится в [GitLab](https://gitlab.com/aza954/polyvent). Исходная история сохраняется в GitLab; новые коммиты отражают подготовку, перенос, интеграцию и проверку отдельных этапов.

## Текущий этап

Добавлен каркас серверной части на Spring Boot: точка запуска, Maven Wrapper, настройки PostgreSQL и Checkstyle, API версии и проверка готовности. Авторизация, модель мероприятий, frontend, Docker и CI будут добавляться следующими этапами.

В исходной версии уже реализованы афиша и фильтры, карточки с фотографиями, вход и выход, регистрация аккаунтов, профиль, управление ролями, создание и редактирование мероприятий, модерация и тесты.

Запись студента на мероприятие, отмена участия, раздел «Мои мероприятия» и список участников организатора требуют отдельной реализации. Регистрация аккаунта не означает регистрацию на мероприятие.

## Технологии

- Backend: Java 21, Spring Boot, Spring Security, Spring Data JPA, Flyway и Maven Wrapper.
- Frontend: React, TypeScript и Vite; Node.js 24 для сборки.
- Данные: PostgreSQL 17.
- Сборка и запуск: общий JAR с frontend, Docker и Docker Compose.
- Проверки: Java unit/API-тесты, Vitest, Testing Library и Playwright.
- CI для GitHub планируется через GitHub Actions; конфигурация исходного проекта использует GitLab CI/CD.

Backend использует Java 21, Spring Boot 4.1.2 и Maven Wrapper 3.9.11. Остальные версии фиксируются при переносе соответствующих модулей.

## Сборка серверной части

Нужна Java 21. Maven Wrapper загрузит нужную версию Maven при первом запуске. На Windows из корня репозитория:

```powershell
cd backend
.\mvnw.cmd -B -ntp checkstyle:check package
```

На Linux и macOS используется `./mvnw` с теми же параметрами. Готовый файл — `backend/target/polyvent.jar` относительно корня репозитория. Автотесты появятся вместе с функциональными модулями; сейчас команда проверяет стиль и сборку каркаса.

## Запуск серверной части

Нужна заранее созданная локальная база PostgreSQL. Укажите её адрес и свои учётные данные в окружении. Из каталога `backend` на Windows:

```powershell
$env:DB_URL = 'jdbc:postgresql://localhost:5432/polyvent'
$env:DB_USERNAME = 'polyvent'
$env:DB_PASSWORD = '<пароль локальной базы>'
java -jar target/polyvent.jar
```

По умолчанию сервер слушает порт 8080. `APP_PORT` меняет порт, а `APP_VERSION` задаёт версию в ответе API; значение версии по умолчанию — `local`.

- `GET /api/info` возвращает название и версию приложения.
- `GET /actuator/health/readiness` проверяет готовность сервера и подключение к БД.

Главная страница появится после переноса frontend. Подготовка локальной БД и Docker Compose войдут в отдельный этап; миграции модели мероприятий ещё не добавлены.

## Совместная работа

Основная ветка — `main`. После инициализации изменения готовятся в тематических ветках и объединяются через Pull Request с проверкой другим участником команды. В задаче и PR указываются требование, содержание изменения и фактический результат проверки. Для связи с Jira используются реальные ключи задач.

Секреты, локальные `.env`, базы данных, каталоги зависимостей и результаты сборки в репозиторий не добавляются. Примеры конфигурации будут храниться отдельно от действующих учётных данных.
